# Codex Viewer

Windows 浏览器里的本地 Codex 工作台；Node.js 和 `codex app-server` 都运行在 WSL，不需要 Codex Desktop。

支持 Codex 与可选的 Antigravity Rust app-server 共存。同一模型菜单选择后端，切换时复用各自原生会话并增量交付历史。旧 ACP 接入已移除；旧 `antigravity:` 会话保留历史，新后端使用 `agy:` 身份。

### 接入 Antigravity

先在相邻 `../antigravity-acp-exoskeleton` 构建后端。Viewer 自动查找 `target/release/antigravity-app-server`、`target/debug/antigravity-app-server`，最后兼容旧 `target/debug/antigravity-harness`；也可用 `VIEWER_AGY_BINARY` 指定明确的二进制路径。未安装时继续使用 Codex。

原生 runtime 使用 App 2.24.0 的 `language_server`，由后端严格校验哈希。`AGY_APP_CORE_BINARY` 默认指向 `~/.local/opt/antigravity-app/2.24.0/language_server`。Viewer 将后端状态固定在自己的数据目录 `antigravity-app-server/`；`AGY_APP_AUTH_HOME` 默认是该目录下的 `app-auth/`，独立标题进程共享认证目录，但使用自己的临时会话目录。首次使用须按后端 README 完成原生 `--login`，登录与 Viewer 使用相同的认证目录。旧 `AGY_EXTERNAL_BINARY`、`AGY_PERSONAL_CREDENTIALS` 和 API key 不再用于模型执行。

旧 SDK 创建的 `agy:` 会话保留为只读历史，不尝试续跑；界面提示新建会话。新 App core 会话支持原生恢复。构建和配置更新不会自动重启正在运行的 Viewer。

模型及思考档位来自后端账户目录。Google 会话支持 Plan、执行中追加、Goal、Skills 和子任务；切换后启动 Goal 会先注入历史，无需额外用户轮次。Google／外部模型分别显示 5 小时和 7 天额度，缺失窗口显示未知；Codex 保留原有周额度与重置卡。单个后端的列表或额度读取失败会单独显示，并保留另一个后端的结果。自动审批由后端 Guardian 执行，默认会调用 Codex 审批模型并使用其额度。

修改和构建不会重启现有服务；实际加载需在任务空闲时使用既有重启流程。


## 为什么做这个

我们想要的是 **Gemini 网页版那样易读、易复制的回答体验，加上 Codex CLI 的实际工作能力**。终端适合执行任务，但长篇 Markdown、公式、图片和多个并行对话，在网页里更容易阅读和管理。这个项目把交互搬进浏览器，执行仍交给 WSL 中已有的 Codex。

- **看渲染，拿源码。** 公式、表格和代码应当清晰可读；原始 Markdown / LaTeX 始终保留，渲染只是展示层，不能损坏复制、历史或后续使用。
- **少一点来回切换。** 用“项目 → 对话”管理多任务，直接粘贴截图、拖入文件，在同一个界面选择模型、思考强度、Plan 和 Skills。
- **看得懂正在发生什么。** 命令、输出、等待、审批和失败有明确区别；代码与命令共享高亮能力，输出保留 ANSI 颜色，但展示不等于执行。
- **适合长时间阅读。** 以暖色、低眩光和现代感为方向，正文使用衬线字体，界面保持简洁，代码使用等宽字体；颜色表达含义，不把整个界面涂成一种状态色。“防蓝光”在这里是视觉设计偏好，不是护眼功效承诺。

它定位于本地、单用户的轻量工作台，不另造 Agent 框架，也不追求完整复刻 Desktop 或终端。复用现有 CLI 的登录、会话与执行能力；审批和工作目录应当透明可见。**运行在 WSL 不代表与 Windows 完全隔离**，浏览器也不是额外的执行沙箱，具体边界见下文。

## 启动

需要 Node.js 24+、已登录的 Codex CLI（开发验证版本 0.154.0）。在 WSL 项目目录执行：

```sh
npm ci
npm run build
npm start -- --root /home/andantex/projects
```

打开启动时打印的完整链接。服务只监听 `127.0.0.1:8787`，浏览器登录后会移除 URL 中的令牌。不要分享启动链接。有效页面／API 请求会同步续期登录与 Cookie，连续 24 小时无访问才过期；SSE 心跳本身不续期。登录过期时停止自动重连并保留草稿，请重新打开启动链接；意外重启服务也需要重新登录。默认授权目录为 `~/projects`，可重复传入 `--root`，通过 `--port` 更改端口。

侧栏新建/切换任务；任务在服务端继续运行，关浏览器不会中断。刷新会恢复历史和待审批请求。停止 WSL、服务或 Codex 子进程则不是“后台继续”：连接恢复后查询状态，不自动重发用户操作。

新建任务时可点“浏览本地文件夹…”打开 Windows 系统选择器，选择 Windows 盘或 WSL 目录；也可在页面内浏览目录、输入 WSL 路径或 Windows 路径。系统选择器确认的目录会加入项目位置，保存在服务数据目录的 `projects.json`，重启后仍可访问。直接输入路径只能浏览已加入的范围；新增位置请使用系统选择器。

流式消息按轮次和消息 ID 合并，不把部分轮次更新当成完整历史覆盖。已完成的会话重新打开时会读取持久化记录，修复旧的漏项缓存；读取期间若有新事件到达，则保留实时状态。这个过程只同步显示，不重新发送用户消息。

## 功能与边界

- 数学宏随材料上下文渲染：从当前会话先前的用户文本、成功工具输出中提取 `\newcommand`、`\renewcommand`、`\providecommand`、`\DeclareMathOperator` 和简单 `\def` / `\gdef` 声明，按出现顺序建立每条回复的默认宏环境；不自动读取文件，不跨会话共享，也不让后续定义改变旧回复。公式内显式定义优先，缓存包含宏上下文。未知宏或 KaTeX 不支持的语法保留公式源码并在悬停时说明原因，不猜测数学含义；不支持完整 LaTeX 文档编译、任意宏包或带默认可选参数的 `\newcommand`。
- GFM Markdown、表格、代码和 KaTeX。行内公式支持 `$…$` / `\(…\)`，独立公式支持 `$$…$$` / `\[…\]`；代码和链接地址不按括号公式解析。未闭合的括号公式先显示原文，闭合后排版；分隔符扫描上限 32768 字符，超长输入退回文本。不注入模型提示词，不改写历史。完整回复的“复制 Markdown”保留原文；“复制代码”复制整块纯代码。代码块内选区仅复制选中文字，保留缩进和换行，不添加围栏；跨正文选择时完整覆盖的代码块保留原始围栏，部分覆盖只复制所选代码。公式、行内代码和链接保留原始源码分隔符；普通文本不补回粗体等标记。
- 文件选择、拖放、截图粘贴；PNG/JPEG/WebP 显示缩略图并通过 `localImage` 发送，其他文件通过 WSL 文件路径交给 Codex。不自动运行上传内容。每轮最多 10 个、单文件 25 MiB、总空间 512 MiB。
- 单次批准、拒绝、取消、问题回答，并独立显示审批原因和操作范围。检测到 Windows 路径或程序的审批会显示命中依据，并在卡片上一次确认，不再弹出第二个确认窗口；“持续授权选项”按 Codex 提供的范围显示本会话授权、保存命令前缀规则或主机网络规则；保存规则跨会话生效，界面会显示具体前缀或主机。后端只接受当前请求提供的选项，不接受浏览器自拟规则。多行 Python 等原始命令不会因 JSON 换行转义而被误判。
- Windows 互操作保留。**这是审批提示，不是 Windows 隔离沙箱**；命令间接调用或其他路径表示不一定被识别。`--root` 和系统选择器确认的项目目录限定 UI 可选范围，不等于限制模型读取范围。真正的执行边界由 Codex/WSL 决定。
- 每轮使用 `workspaceWrite`、`on-request`、默认禁止网络；创建、恢复和开始每轮前，读取该项目的有效 Codex 配置并显式传入审批审查方式（例如 `auto_review`），避免旧会话继续保留人工审批。已加载会话忽略恢复参数时，调用 `thread/settings/update` 并读回确认；运行中的轮次通过 `turn/settings/update` 更新后续步骤，已经捕获的步骤及待审批请求仍保留原方式。输入区显示 Codex 返回的实际审批方式。保存包含整段 shell 脚本的规则只匹配该脚本，内容变化仍可能询问。不使用 unrestricted/danger-full-access。既有 MCP 工具仍可能拥有独立权限，不能把 WebUI 当成整个主机的安全边界。
- 普通 MCP 工具结果沿用工具记录展示，可展开和复制。MCP 表单与 URL 问答仍显示在待处理区，由用户提交、拒绝或取消。
- 仅本地单用户；校验 Host/Origin、HttpOnly SameSite cookie。Markdown 不允许原始 HTML、危险链接或自动下载远程图片。没有 LAN、SSH、PTY、Git 管理或 Desktop 功能克隆。

## 日常操作

- 底部额度栏可点“重置额度”，核对剩余重置卡后，再点“确认使用 1 张重置卡”。沿用 Codex 原生额度重置，结果与剩余次数同步到各标签页；请求失败不自动重试，再次确认沿用同一次请求，避免重复使用重置卡。对话、草稿和项目文件保留。
- 界面仅面向桌面宽屏，不再维护窄屏或移动端适配。布局为项目列表、左侧 Watchdog、主对话、右侧 Subagents；两侧面板独立滚动，可折叠并记住选择。
- 主智能体可通过 MCP 派发 Codex 子任务，独立副本中的结果自动回传，采用修改由主智能体决定。跨后端切换入口已移除。
- 子任务副本不设文件数或总容量门槛；文件按流计算哈希，优先克隆文件，文件系统不支持时直接复制。`.runs` 运行历史和虚拟环境等缓存不进入新副本，实际任务数据仍保留；旧副本已纳入基线的历史文件继续正常比较。合并回写使用磁盘载荷和可恢复日志，避免把大文件嵌入 JSON 或整块载入 Viewer 内存。
- Subagents 按父子层级显示当前对话的派发任务、状态和最近输出。点击节点在右侧查看完整只读记录，主对话与草稿保持原位；原生子代理保持只读，Viewer 派发的子任务支持追加、停止和审批。现有 SSE 即时更新，面板可见且有任务执行时每两秒补查只读记录；磁盘尚未保存的输出只能在收到实时事件后显示。读取失败保留已有内容，可重试；刷新和重连恢复层级，不恢复或修改子代理配置。

- 侧栏底部“重启整个后端”会关闭 Viewer HTTP 服务、应用沙箱和 Codex 子进程，重新执行 Viewer 并启动新的 Codex，加载后端代码及 Codex 配置。浏览器自动重连并刷新页面，加载已构建的新版前端；各标签页分别恢复当前对话、未发送草稿、附件和所选 Skills，保留登录，不重发消息。有运行中的任务、待审批请求、上传或 Watchdog 检查时须先结束；无法确认会话已保存时拒绝重启。60 秒未恢复会提示检查服务，不自动再次重启；无法暂存草稿时保留页面并提示手动处理。前端源码修改仍需 `npm run build`；普通“刷新”只同步页面状态。此功能使用 Node 24 在 WSL/Linux 下的进程替换，保留 systemd 托管关系，无需授予网页 systemctl 权限。
- 运行中仍可输入、粘贴附件和连续发送多条消息：Enter /“排队追加”通过原生 `turn/steer` 追加到当前轮次，由 Codex 在下次接收输入时处理；“打断并发送全部”先停止当前轮次，确认结束后按顺序发送全部待接收消息，再附上输入框内容，输入框为空也可发送整队。已经接收的消息按 ID 排除，附件和 Skills 随各条消息保留；单独“停止”留下尚未接收的队列，之后可点“发送全部”。排队追加沿用当前轮次模型设置，待生效的设置保留到下一轮；失败时保留草稿和队列，不自动重发。
- 侧栏按最近的 Git 仓库根目录显示“项目 → 对话”，兼容子目录和 worktree；非 Git 目录或仓库根超出授权范围时按 cwd 分组。每个项目的会话区独立滚动，最高为 360px 与窗口高度 40% 中的较小值，项目标题位于会话区外。首屏只取最近 50 条元数据，内外列表触底继续分页；短项目可点“加载更早会话”。同项目历史可跨多个全局分页，逐页合并，折叠或切换项目后停止其后续扫描；失败可重试，不丢弃已加载内容。数量和搜索仅覆盖已加载会话，工作目录不可用的历史继续隐藏。右边缘可拖动调整宽度，双击恢复默认，也可聚焦后使用方向键调整；侧栏宽度和折叠状态保存在浏览器。
- 新对话首条文字消息发送成功后，立即显示首句预览，后台通过 Codex 额外概括一次任务目的，生成最多 40 字符的短标题。会话沿用当前模型。概括使用独立、只读且不保存的临时会话；失败时保留预览。已有标题及生成期间的手动改名优先，纯附件消息使用“附件任务”。顶部“重命名”可保存 1–120 字符的自定义标题；保存失败明确提示，不影响已经发送的任务。启动服务不会自动批量改名旧会话。
- 标题更新通知会同步到已连接的网页；点击侧栏“刷新”、重新打开对话或刷新页面，会重新读取 Codex 标题与预览，保留进行中的消息和状态。CLI 与 WebUI 必须使用同一个 `CODEX_HOME` / 会话存储；其他进程的改名不保证实时广播，可手动刷新同步。
- 异步提问显示独立卡片，可选择建议选项或填写回答，点击“发送回答”后通过现有消息通道提交；运行中排队追加，空闲时继续对话。回答草稿随会话保存，不夹带或清空主输入框的文字、附件和 Skills。卡片区分待回答、已排队和已接收；普通消息中的问句不会被自动当成提问接口，异步提问也不会强制暂停任务。
- Watchdog：在对话中说“每小时检查这个任务，严重错误时停止并修复”，Codex 会从当前上下文撰写并保存完整监控指令；缺少关键任务信息时先询问。管理入口只在当前会话左侧的 Watchdog 栏，标题旁 ＋ 可新建。卡片展示名称、状态、三行可展开指令、频率、模型／思考强度及执行时间，可编辑、暂停／启用、立即检查、删除，或通过“查看最近执行”跳回原对话；不另设巡检报告页面。同一会话可有多个独立任务，后续修改前台模型不会改变已保存的监控设置。
- 调度方式支持固定间隔、每天、每 N 天、每周勾选星期集合、单次日期时间；每天／每 N 天以开始日期为锚点，每条日历规则每天一个时刻。日期与时刻使用界面显示的后端本地时区，与浏览器时区无关，也可在对话中说“每周一、三、五 9 点检查”或“明天 10 点执行一次”。旧固定间隔任务直接兼容。
- 固定间隔创建或手动启用后经过一个间隔首次检查，“立即检查”重置计时起点；日历重复任务取下一个未来时刻，“立即检查”保留原时间表。检查沿用原会话，等待当前工作、提问或审批处理完毕；同会话按到期时间依次运行。错过多个时刻只合并检查一次，长时间执行结束后排到下一个未来时刻。暂停／删除停止后续调度，当前检查继续；对话中的“停止”会中断本轮并暂停相应 Watchdog。
- 重复任务通过报告“继续”续排，“完成”表示整个目标已达到并停止后续执行。单次任务成功且有有效报告后结束，即使报告“继续”也不重复；尚未完成但已过期的单次任务在空闲后补执行。完成后需修改到未来时间再启用，或使用“立即检查”明确重跑；运行中只修改指令不会重放同一预约，改期则保留新预约。
- 后端将任务及实际执行的指令／模型快照、轮次和结果存入应用数据目录的 `watchdogs.sqlite`。巡检只需通过 `watchdog_report` 提交运行 ID 与继续／完成／需要处理，完整发现写在原对话中；旧调用的摘要仍兼容。调度结果在原生轮次成功结束后确认；执行失败、缺少结果或需要输入时暂停。提交超时先核对原生消息记录，无法确认时不会自动重发；显式重新启用前核对空闲状态。服务重启保留任务和历史，未确认结束的检查暂停待核实。关闭浏览器不影响计划；电脑、WSL 和后端服务必须保持运行。
- Watchdog 的五个内置管理工具通过启动参数挂载到 App Server，旧会话恢复后也可调用；普通对话和定时巡检均可按用户指令删除本会话任务，保留历史且不打断本轮，巡检期间其他管理操作仍受限。仅这一本地管理服务免重复确认，检查中的命令和文件操作仍使用已有审批与沙箱。任务不会创建 `/goal`，不会自行扩展保存的停止、修复或重启权限。不提供 Cron、月份规则、多时区选择或关闭浏览器后的外部推送。
- 输入区可选模型、思考强度和普通／Plan 模式。选项来自实际 App Server；“已生效”和“下一轮”分开显示。更改不打断当前轮次，切出 Plan 不会自动开始实现。旧 CLI 不支持的入口显示错误并禁用，不自动升级或改写提示词冒充协议能力。
- Goal 独立于普通／Plan 模式：点击输入区的 **Goal** 设置目标和可选 token 预算，也可以直接说“为这项任务创建 Goal，完成条件是……，预算 20000 tokens”，让模型调用原生 `create_goal`；原生 `get_goal` / `update_goal` 同样可用。Viewer 仅为自己的 App Server 开启 goals，不修改全局配置。模型和界面操作同步到同一条状态栏，显示目标、六种原生状态、累计 token 和耗时。
- Goal 的“暂停”停止后续续跑、保留当前轮次；对话“停止”先暂停 Goal 再中断。“打断并发送”在新消息提交确认后恢复原先 active 的同一目标，失败或结果不明时保持暂停。继续使用界面当前选择的模型、思考强度和普通／Plan 模式；切换模式本身不修改目标。预算留空为无上限，调整预算保留用量，替换目标重置用量，清除保留对话历史。持久化、续跑与计量由 Codex 管理；轮次结束不等于目标完成。
- Goal active 时同会话的 Watchdog 等待，Watchdog 运行时暂不允许从界面激活 Goal；主动重启后端也会检查轮次间隙中的 active Goal。重连重新读取原生目标，读取失败显示“状态待同步”，不会自动重试激活。服务和机器需要保持运行，关闭浏览器不影响原生续跑。
- 所有新建入口可选择模型和“实验上下文管理”，默认关闭，仅作用于新会话。根据当前模型能力、ChatGPT 订阅和项目提供方启用选项；能力未知时显示原因，不猜测支持。CLI 0.154 的 `model/list` 尚未返回该能力，暂从同一 `CODEX_HOME` 中一天内更新的模型目录补充，不写死模型名称。选项通过 `thread/start` / `thread/resume` 的配置覆盖传入同一个 App Server，并按会话保存于应用数据目录的 `thread-settings/`；不改全局配置。开启后的会话只允许切换到兼容模型，旧会话不自动迁移。
- Skills 面板的“用于本轮”添加消息标签；“全局：已启用／已禁用”会通过 Codex 配置接口持久修改该 Skill 状态，影响 CLI 和其他客户端。全局开关不修改 Skill 文件、不安装插件。每次写入后检查有效状态；策略阻止更改时显示错误。
- 文件修改直接显示文件列表、变更类型与增删行数，点击文件展开带行号和代码高亮的红绿 diff。“放大查看”打开文件导航与左右对比，可切换单栏并记住选择；主对话和子代理共用展示。每张卡片对应这次工具操作，不是工作区累计 Git diff。原始 diff／文件内容可完整复制，代码选区不带行号和增删符号。大文件每批显示 500 行，超过 32768 字符保留行颜色但省略语法高亮；缺失、非文本或不完整差异显示原因与现有原文，不读取当前文件补造历史。
- 两次回复之间的思考、工具调用和上下文压缩归入“思考与工具”，执行时默认展开，下一段回复开始或本轮结束后默认收起。可手动展开／收起，切换会话保留选择；查找会自动展开命中的记录。待回答的问题与交互式 MCP Apps 保持可见。展开后的思考摘要使用普通字重的 Markdown，相邻摘要共用状态标签；主对话和子代理共用展示。
- 其他活动默认显示一行摘要，有搜索详情或命令输出时可展开。状态文字、颜色、图标及运行耗时区分等待与结果，不读取或承诺提供隐藏推理。
- 长对话仅渲染视口附近的消息。切换时先显示已缓存历史，再后台同步；同步失败保留内容并提供重试，成功前不能提交。主对话和子代理分别保留阅读位置，最近 8 个会话保留命令／文件展开状态；页面刷新后重新读取历史。
- “查找对话”或 Ctrl/Cmd+F 搜索当前对话完整记录，包括尚未渲染的正文、公开工具输出、diff 和已提交回答。结果按消息计数，支持上一条／下一条及命中摘要；子代理阅读区聚焦后使用独立查找。原生浏览器查找只能覆盖已挂载内容。
- 中文强调使用 CJK 友好的 Markdown 解析，修复 `**句号在内。**后面紧接中文` 的加粗；原始 Markdown 与源码复制保持不变。
- 本地文件引用展示文件名和行号。悬停、聚焦或点击显示完整路径及前后各五行；Ctrl+点击或“使用系统默认应用打开”按钮调用系统文件关联。WSL 路径转换后交给 Windows，文件夹打开资源管理器；其他桌面系统使用自身默认程序。“在文件夹中显示”在 Windows 资源管理器中选中目标文件或文件夹；macOS 使用 Finder，其他 Linux 桌面打开所在目录。行号只用于预览，不附加到实际打开路径。程序只在用户明确点击后启动，失败会显示错误。
- 文件引用支持绝对路径、相对 cwd 的路径、`:行号[:列号]` 和 `#L行号`。打开允许授权目录内的非隐藏普通文件及文件夹；文字预览只允许 UTF-8 普通文件，最大 256 KiB，文件夹显示类型提示。越界、隐藏配置、二进制预览、失效行号均明确报错。文件引用装饰与预览不会进入源码复制。
- 回复中的本地 Markdown 图片可直接显示，支持授权目录内、非隐藏的 PNG/JPEG/WebP，最大 25 MiB；按实际文件内容识别格式，自动适应阅读区宽度。复制仍保留原始 Markdown 图片路径，远程图片不自动加载。
- `mermaid` 代码块默认显示浅色图表，可切换／复制源码、放大拖动和下载 SVG。放大窗口支持适应窗口、原始大小、最高 400% 缩放及 Esc 返回；超大图可缩小至适应窗口。页面与下载使用同一份图表。图表接近视口时才加载与排版；流式围栏闭合后渲染，后续正文追加保留图表状态，完成消息中的未闭合围栏也会尝试渲染。源码超过 32,000 字符、超过 Mermaid 的 500 条边限制或解析失败时保留源码并显示原因。图内配置固定，不加载图片、外部资源或执行点击动作；不支持需要 HTML 标签的图表内容。完整 Markdown 与跨正文完整选中图块时保留原始围栏；源码区内选区只复制所选代码。
- 外部网页链接显示域名，悬停／聚焦显示完整 URL 并可复制；不自动访问网页获取摘要。系统通知只有用户主动授权且页面隐藏时才发送，刷新不重复提醒。

历史仍由 Codex 管理。上传副本保存到 `~/.local/share/codex-viewer/attachments`（尊重 `XDG_DATA_HOME`，也可指定 `--data-dir`），30 天后自动删除，仅删除本应用命名的上传副本；原文件不受影响，旧任务附件届时可能无法再次读取。文本草稿保存在此浏览器 localStorage，附件草稿仅保存在当前页面内存；手动刷新前请先发送附件。“重启整个后端”的自动刷新使用各标签页独立的 sessionStorage 临时保留草稿及附件，恢复后清除该临时副本。

## 双击启动与 WSL 自启

WSL 已启用 systemd 时：

```sh
npm run service:install -- /home/andantex/projects
systemctl --user enable --now codex-viewer
loginctl enable-linger "$USER"
npm run shortcut:install
```

桌面和 Windows 开始菜单会出现 **Codex Viewer**。双击会启动对应 WSL 发行版和服务，等待就绪，读取最新登录链接并打开默认浏览器；无需复制链接。重复打开不会重启正在运行的任务，也不会重复创建后台驻留进程。WSL 中也可以运行 `npm run open`；`node scripts/open.ts --check` 仅检查服务就绪，不打开浏览器。

浏览器标签、收藏夹、侧栏、通知和 Windows 快捷方式共用 `c/` 标志。原图保存在 `web/assets/logo-source.png`；`node scripts/icons.mjs` 用已有 Chromium 生成 PNG 和包含 16–256 px 的 ICO，`npm run shortcut:install -- --icon-only` 只更新现有 Viewer 快捷方式的图标。Windows 图标副本保存在本机 `%LOCALAPPDATA%\Codex Viewer\icon.ico`，WSL 未启动时也能显示。

`enable` 与 `enable-linger` 使用户服务随该 WSL 发行版启动；后者允许用户服务在没有交互登录时运行。这不等于 Windows 登录时自动启动 WSL。WSL 的 systemd 服务本身不会阻止发行版空闲退出，因此双击入口在后台保留一个等待进程，直到服务停止或 WSL 关闭。关闭浏览器后任务和 Watchdog 可以继续；电脑仍需保持开机、唤醒。停止服务可用 `systemctl --user stop codex-viewer`，取消服务自启可用 `systemctl --user disable codex-viewer`。

安装命令只创建新文件，不覆盖已有 unit 或快捷方式；`service:install` 本身不启用或启动服务。unit 保存安装时的 Node 路径、PATH、已设置的代理变量、`CODEX_HOME` / `XDG_DATA_HOME` 及 `WSL_DISTRO_NAME` / `WSLENV`。WSL 变量让 VS Code 选择 Remote WSL 启动分支；不保存每次会话都会变化的 `WSL_INTEROP` socket。迁移项目或 Node、改变代理后需更新 unit，迁移项目或 Node 后也需重建快捷方式。服务启动链接位于 `$XDG_RUNTIME_DIR/codex-viewer-<uid>/url`，未设置该变量时位于 `/tmp/codex-viewer-<uid>/url`；也可用 `--runtime-dir` 指定。快捷方式使用标准用户 runtime 目录，适配上面的默认 unit。不修改 Codex 全局配置、不安装 Windows 服务。

## 实现与参考

Vue 3 + TypeScript + Vite，后端沿用 Node HTTP/SSE；unified/remark 解析、rehype-sanitize 清洗、KaTeX 排版。原始 Markdown 与展示分离，AST 源码位置用于复制，服务端有序事件与快照用于重连。

组件通过具名操作访问统一会话状态，HTTP/SSE 连接由应用生命周期管理；前后端复用 `shared/protocol.ts` 的事件合并规则。会话读取按请求代次处理，快照与实时事件按会话合并，选区存在时只暂停对话显示更新。模块职责、资源释放和后续扩展方式见 [ARCHITECTURE.md](ARCHITECTURE.md)。本轮建立扩展边界，运行时插件热插拔留待具体扩展需求实现。

代码块与命令共用 `web/highlight.ts` 的 lowlight 高亮，命令输出通过同一模块安全呈现 ANSI 颜色。不猜测普通日志的语言；折叠内容按需渲染，缓存有上限，超长文本退回纯文本，复制仍取源码。这里不是完整终端模拟器，不重放光标控制或执行输出中的链接。

Mermaid 12 按需加载，SVG 缓存最多 32 项、总计 4 MiB；图表布局串行执行，进行中的布局无法强制中止，过期结果不会重新插入页面。`lodash-es` 覆盖到 4.18.1，修复 Mermaid 的 Chevrotain 间接锁定旧版本带来的依赖漏洞。

协议以已安装 CLI 生成的 schema 为准；官方文档：[Codex App Server](https://developers.openai.com/codex/app-server/)。先保持这一条运行链路；只有需要原生窗口、系统托盘或独立打包时才考虑 Rust/Tauri。

## Vault Assistant（Obsidian 桌面插件）

插件默认打开 vault 内的独立窗口，复用本服务和 Codex 原生会话。Windows 运行 Obsidian，WSL 运行后端。插件颜色跟随当前 vault 的深浅主题；浏览器 Viewer 保留自己的阅读主题。

Viewer 网页与 Obsidian 插件使用同一个源码主干、后端和应用数据目录。日常开发统一在 `codex-viewer` 主目录进行；`vault-assistant` 旧工作目录仅保留历史，不再独立维护或部署后端。

构建：npm run build:obsidian。将 dist-obsidian 中的 main.js、styles.css、manifest.json 放到 vault 的 .obsidian/plugins/vault-assistant，启用插件。在插件设置中粘贴与网页相同的 Viewer 启动链接并连接当前 vault。链接只用于配对，长期凭据进入本机 Obsidian SecretStorage；插件配置不保存原始令牌。插件可访问后端已授权目录内的项目会话、文件和审批；vault 配对用于笔记入口及文件打开，不再作为会话隔离边界。撤销配对或重新配对会使旧凭据失效。

插件侧栏仅显示当前 Vault 内的会话，新对话默认在当前 Vault 创建。跨项目会话通过转发／引用选择器选择，不进入插件侧栏；顶部显示当前会话的执行目录。跨项目可转发选中的聊天记录，或授权目标会话持续只读引用来源 Session；引用不改变工作目录，也不扩大目标会话的文件写入权限。Vault 内文件在 Obsidian 打开，其他已授权项目文件使用系统应用打开。

助手会话以当前 vault 为工作目录；Codex 按需搜索、读取文件。没有自动跟随阅读、固定材料、发送全文或材料栏。在文件右键菜单选择“讨论该文章”，或在 Markdown 编辑器、阅读视图及 PDF 中选中文字后右键选择“讨论该选区”，打开独立助手窗口、新建会话并预填可编辑草稿。草稿包含 Obsidian 文件链接、准确的 vault 相对路径和用户选区；不会自动发送，也不覆盖其他会话的草稿。命令面板提供当前文章和编辑器选区的同等入口。

通用 CLI：node scripts/vault-cli.ts <vault-name> <command> [parameters...]。固定通过 PowerShell 7 调用 Obsidian.com，参数独立传递；执行保留 Codex 的原生审批。CLI 帮助以本机版本为准，不把退出码 0 当作操作完成的充分证据。Windows CLI 和脚本工具不构成额外沙箱。

历史由 Codex 保存。vault 绑定保存在服务数据目录；旧版本材料记录保留，但新会话不注册 material_read、不传编辑器快照。普通讨论不自动改笔记；明确要求修改时按既有授权执行，保存讨论按钮写入用户选择的 Markdown 笔记。关闭助手窗口不会取消后端任务，断线不自动重发写操作。

v1 边界：每个 vault 一个助手视图，可迁移到普通标签页，界面跟随当前 vault 主题。插件 v1 不承载交互式 MCP Apps；这些仍可在浏览器 Viewer 使用。

助手复用 Viewer 的 Sidebar，按项目分组，包含新对话、会话标题和目录搜索、当前对话全文查找、重命名、删除与保存讨论。删除调用 Codex thread/archive，移出列表并保留原生归档；正在运行、待审批、有活动 Goal 或定时监控的会话须先停止。

更新插件：在统一源码目录运行 npm run build:obsidian，然后仅复制 dist-obsidian 的 main.js、styles.css、manifest.json 到 knowbase 的插件目录，保留 data.json；运行 node scripts/vault-cli.ts knowbase plugin:reload id=vault-assistant。已有配对和会话草稿无需重建。后端更新仍需在任务空闲时使用 Viewer 的“重启整个后端”；插件收到重启通知后原地重连，不刷新 Obsidian。

迁移数据：先确认两个后端均空闲并停止旧 assistant，再执行 `node scripts/merge-assistant-data.ts <旧数据目录> <Viewer 数据目录> <新备份目录>`。脚本保留 Viewer 原记录，合并配对、引用、巡检、附件与会话设置；SQLite 使用 backup API 保留 WAL 数据，附件元数据路径随目录迁移。有冲突则报错，不覆盖。随后让插件连接统一后端并停用旧服务。原生对话仍由相同 CODEX_HOME 管理，无需复制对话记录。

## 跨会话引用

- **转发聊天记录**：在来源会话点“选择转发”，逐条选择正文；工具记录必须展开后明确勾选，折叠工具不会自动选中。点“转发到…”先选择目标文件夹，再选择其中的会话，或选择“在此文件夹新建对话”，预览完整内容，再加入目标草稿。目标已有文字会保留，最后由用户发送。固定记录不随来源变化，不授予原会话读取权限，也不携带图片或文件实体。
- **引用 Session**：在目标输入区点“＋ Session”，先选来源文件夹再选会话；也可从来源会话转发 Session，先选目标文件夹，再选会话或在该文件夹新建对话。只有发送后才授予目标会话持续只读权限；AI 可按需列出、搜索、分段读取来源的最新已完成历史。后续轮次仍可读取，在输入区“已授权 Session”中撤销后停止后续读取；撤销不会抹去先前已进入上下文的内容。
- 引用限于共同后端的已授权目录，可跨 Vault 和项目。引用不递归授予源会话的其他引用、子代理或文件访问权限。只读工具从原生调用元数据确认目标会话，不接受模型自行指定目标身份。
- 快照保存完整结构化文本，超限明确拒绝，不静默截断；每次发送引用合计上限 64 KiB。Session 默认只读正文，工具记录需明确请求；每页默认 16 KiB、最多 64 KiB，游标固定当次读取视图并在 10 分钟后过期。已发送引用与授权保存在应用数据目录的 `references.sqlite`，服务重启后保留。
- 新客户端遇到旧后端时隐藏创建入口并保留已有引用草稿；旧客户端仍可使用原有发送协议。排队、插话、重载沿用同一提交标识；提交结果不明时核对历史，避免自动重复发送。

验证：`node --test test/references.test.ts`、`npx playwright test test/references.browser.ts`。`node scripts/check-references.ts` 使用临时 Codex 配置进行真实模型调用，验证旧会话恢复、按需读取、重启和撤销；需要现有登录，会消耗模型额度，不修改全局配置。

网页与 Obsidian 插件连接同一后端时可双向转发和引用。已发送的引用随目标会话在两端显示；未发送草稿保留在发起端。
