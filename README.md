# Codex Viewer

Windows 浏览器里的本地 Codex 工作台；Node.js 和 `codex app-server` 都运行在 WSL，不需要 Codex Desktop。

## 为什么做这个

我们想要的是 **Gemini 网页版那样易读、易复制的回答体验，加上 Codex CLI 的实际工作能力**。终端适合执行任务，但长篇 Markdown、公式、图片和多个并行对话，在网页里更容易阅读和管理。这个项目把交互搬进浏览器，执行仍交给 WSL 中已有的 Codex。

- **看渲染，拿源码。** 公式、表格和代码应当清晰可读；原始 Markdown / LaTeX 始终保留，渲染只是展示层，不能损坏复制、历史或后续使用。
- **少一点来回切换。** 用“项目 → 对话”管理多任务，直接粘贴截图、拖入文件，在同一个界面选择模型、思考强度、Plan 和 Skills。
- **看得懂正在发生什么。** 命令、输出、等待、审批和失败有明确区别；代码与命令共享高亮能力，输出保留 ANSI 颜色，但展示不等于执行。
- **适合长时间阅读。** 以暖色、低眩光和现代感为方向，正文使用衬线字体，界面保持简洁，代码使用等宽字体；颜色表达含义，不把整个界面涂成一种状态色。“防蓝光”在这里是视觉设计偏好，不是护眼功效承诺。

它定位于本地、单用户的轻量工作台，不另造 Agent 框架，也不追求完整复刻 Desktop 或终端。复用现有 CLI 的登录、会话与执行能力；审批和工作目录应当透明可见。**运行在 WSL 不代表与 Windows 完全隔离**，浏览器也不是额外的执行沙箱，具体边界见下文。

## 启动

需要 Node.js 24+、已登录的 Codex CLI（开发验证版本 0.153.4）。在 WSL 项目目录执行：

```sh
npm ci
npm run build
npm start -- --root /home/andantex/projects
```

打开启动时打印的完整链接。服务只监听 `127.0.0.1:8787`，浏览器登录后会移除 URL 中的令牌。不要分享启动链接。默认授权目录为 `~/projects`，可重复传入 `--root`，通过 `--port` 更改端口。

侧栏新建/切换任务；任务在服务端继续运行，关浏览器不会中断。刷新会恢复历史和待审批请求。停止 WSL、服务或 Codex 子进程则不是“后台继续”：连接恢复后查询状态，不自动重发用户操作。

新建任务时可点“浏览本地文件夹…”打开 Windows 系统选择器，选择 Windows 盘或 WSL 目录；也可在页面内浏览目录、输入 WSL 路径或 Windows 路径。系统选择器确认的目录会加入项目位置，保存在服务数据目录的 `projects.json`，重启后仍可访问。直接输入路径只能浏览已加入的范围；新增位置请使用系统选择器。

流式消息按轮次和消息 ID 合并，不把部分轮次更新当成完整历史覆盖。已完成的会话重新打开时会读取持久化记录，修复旧的漏项缓存；读取期间若有新事件到达，则保留实时状态。这个过程只同步显示，不重新发送用户消息。

## 功能与边界

- GFM Markdown、表格、代码和 KaTeX。行内公式支持 `$…$` / `\(…\)`，独立公式支持 `$$…$$` / `\[…\]`；代码和链接地址不按括号公式解析。未闭合的括号公式先显示原文，闭合后排版；分隔符扫描上限 32768 字符，超长输入退回文本。不注入模型提示词，不改写历史。完整回复的“复制 Markdown”保留原文；“复制代码”只复制代码内容。选区复制时公式、代码、链接作为完整源码单元（保留原始分隔符），普通文本按可见文本复制，不补回粗体等标记。
- 文件选择、拖放、截图粘贴；PNG/JPEG/WebP 显示缩略图并通过 `localImage` 发送，其他文件通过 WSL 文件路径交给 Codex。不自动运行上传内容。每轮最多 10 个、单文件 25 MiB、总空间 512 MiB。
- 单次批准、拒绝、取消、问题回答，并独立显示审批原因和操作范围。检测到 Windows 路径或程序的审批会显示命中依据，并在卡片上一次确认，不再弹出第二个确认窗口；“持续授权选项”按 Codex 提供的范围显示本会话授权、保存命令前缀规则或主机网络规则；保存规则跨会话生效，界面会显示具体前缀或主机。后端只接受当前请求提供的选项，不接受浏览器自拟规则。多行 Python 等原始命令不会因 JSON 换行转义而被误判。
- Windows 互操作保留。**这是审批提示，不是 Windows 隔离沙箱**；命令间接调用或其他路径表示不一定被识别。`--root` 和系统选择器确认的项目目录限定 UI 可选范围，不等于限制模型读取范围。真正的执行边界由 Codex/WSL 决定。
- 每轮使用 `workspaceWrite`、`on-request`、默认禁止网络；创建、恢复和开始每轮前，读取该项目的有效 Codex 配置并显式传入审批审查方式（例如 `auto_review`），避免旧会话继续保留人工审批。已加载会话忽略恢复参数时，调用 `thread/settings/update` 并读回确认；运行中的轮次通过 `turn/settings/update` 更新后续步骤，已经捕获的步骤及待审批请求仍保留原方式。输入区显示 Codex 返回的实际审批方式。保存包含整段 shell 脚本的规则只匹配该脚本，内容变化仍可能询问。不使用 unrestricted/danger-full-access。既有 MCP 工具仍可能拥有独立权限，不能把 WebUI 当成整个主机的安全边界。
- 仅本地单用户；校验 Host/Origin、HttpOnly SameSite cookie。Markdown 不允许原始 HTML、危险链接或自动下载远程图片。没有 LAN、SSH、PTY、Git 管理或 Desktop 功能克隆。

## 日常操作

- 界面仅面向桌面宽屏，不再维护窄屏或移动端适配。布局为项目列表、左侧 Watchdog、主对话、右侧 Subagents；两侧面板独立滚动，可折叠并记住选择。
- Subagents 按父子层级显示当前对话的派发任务、状态和最近输出。点击节点在右侧查看完整只读记录，主对话与草稿保持原位；不提供子代理控制操作。现有 SSE 即时更新，面板可见且有任务执行时每两秒补查只读记录；磁盘尚未保存的输出只能在收到实时事件后显示。读取失败保留已有内容，可重试；刷新和重连恢复层级，不恢复或修改子代理配置。

- 侧栏底部“重启 Codex 后端”会替换全部对话共用的 Codex 进程，用于更新 CLI 后加载新版或重新读取配置。历史、浏览器草稿和附件保留，当前对话自动恢复；不会重发消息。有运行中的任务、待审批请求或 Watchdog 检查时须先结束；无法确认会话已保存时拒绝重启。普通“刷新”只同步页面状态。
- 运行中仍可输入、粘贴附件和连续发送多条消息：Enter /“排队追加”通过原生 `turn/steer` 追加到当前轮次，由 Codex 在下次接收输入时处理；“打断并发送全部”先停止当前轮次，确认结束后按顺序发送全部待接收消息，再附上输入框内容，输入框为空也可发送整队。已经接收的消息按 ID 排除，附件和 Skills 随各条消息保留；单独“停止”留下尚未接收的队列，之后可点“发送全部”。排队追加沿用当前轮次模型设置，待生效的设置保留到下一轮；失败时保留草稿和队列，不自动重发。
- 侧栏按最近的 Git 仓库根目录显示“项目 → 对话”，通过文件夹标题、缩进和分组线区分层级，兼容子目录和 worktree；非 Git 目录或仓库根超出授权范围时按 cwd 分组。右边缘可拖动调整宽度，双击恢复默认，也可聚焦后使用方向键调整。顶栏或侧栏按钮可收起/展开；宽度和折叠状态保存在浏览器。数量为已加载对话数，更多历史仍通过“加载更多”获取。
- 新对话首条文字消息发送成功后，立即显示首句预览，后台使用当前模型额外概括一次任务目的，将最多 40 字符的短标题保存到 Codex。概括使用独立、只读且不保存的临时会话；失败时保留预览。已有标题及生成期间的手动改名优先，纯附件消息使用“附件任务”。顶部“重命名”可保存 1–120 字符的自定义标题；保存失败明确提示，不影响已经发送的任务。启动服务不会自动批量改名旧会话。
- 标题更新通知会同步到已连接的网页；点击侧栏“刷新”、重新打开对话或刷新页面，会重新读取 Codex 标题与预览，保留进行中的消息和状态。CLI 与 WebUI 必须使用同一个 `CODEX_HOME` / 会话存储；其他进程的改名不保证实时广播，可手动刷新同步。
- 异步提问显示独立卡片，可选择建议选项或填写回答，点击“发送回答”后通过现有消息通道提交；运行中排队追加，空闲时继续对话。回答草稿随会话保存，不夹带或清空主输入框的文字、附件和 Skills。卡片区分待回答、已排队和已接收；普通消息中的问句不会被自动当成提问接口，异步提问也不会强制暂停任务。
- Watchdog：在对话中说“每小时检查这个任务，严重错误时停止并修复”，Codex 会从当前上下文撰写并保存完整监控指令；缺少关键任务信息时先询问。左侧当前会话卡片及项目侧栏 **Watchdogs** 可编辑名称、指令、分钟／小时间隔、模型与思考强度，查看历史并跳回对应轮次。同一会话可有多个独立任务。模型默认保存创建时的有效设置，后续修改前台模型不会改变已保存的监控设置。
- 创建与恢复后经过一个间隔首次检查；“立即检查”重置计时起点。检查沿用原会话，等待当前工作、提问或审批处理完毕；同会话按到期时间依次运行。错过多个周期只合并检查一次，长时间修复结束后排到下一个未来周期。暂停／删除停止后续调度，当前检查继续；对话中的“停止”会中断本轮并暂停相应 Watchdog。
- 后端将任务及实际执行的指令／模型快照、轮次和结果存入应用数据目录的 `watchdogs.sqlite`。结果报告在原生轮次成功结束后确认；执行失败、缺少报告或需要输入时暂停并显示原因。提交超时先核对原生消息记录，无法确认时不会自动重发；显式重新启用前核对空闲状态。服务重启保留任务和历史，未确认结束的检查暂停待核实。关闭浏览器不影响计划；电脑、WSL 和后端服务必须保持运行。
- Watchdog 的五个内置管理工具通过启动参数挂载到 App Server，旧会话恢复后也可调用；仅这一本地管理服务免重复确认，检查中的命令和文件操作仍使用已有审批与沙箱。任务不会创建 `/goal`，不会自行扩展保存的停止、修复或重启权限。首版提供固定间隔；没有日历/Cron 或关闭浏览器后的外部推送。
- 输入区可选模型、思考强度和普通／Plan 模式。选项来自实际 App Server；“已生效”和“下一轮”分开显示。更改不打断当前轮次，切出 Plan 不会自动开始实现。旧 CLI 不支持的入口显示错误并禁用，不自动升级或改写提示词冒充协议能力。
- 所有新建入口可选择模型和“实验上下文管理”，默认关闭，仅作用于新会话。根据当前模型能力、ChatGPT 订阅和项目提供方启用选项；能力未知时显示原因，不猜测支持。CLI 0.154 的 `model/list` 尚未返回该能力，暂从同一 `CODEX_HOME` 中一天内更新的模型目录补充，不写死模型名称。选项通过 `thread/start` / `thread/resume` 的配置覆盖传入同一个 App Server，并按会话保存于应用数据目录的 `thread-settings/`；不改全局配置。开启后的会话只允许切换到兼容模型，旧会话不自动迁移。
- Skills 面板的“用于本轮”添加消息标签；“全局：已启用／已禁用”会通过 Codex 配置接口持久修改该 Skill 状态，影响 CLI 和其他客户端。全局开关不修改 Skill 文件、不安装插件。每次写入后检查有效状态；策略阻止更改时显示错误。
- 活动只显示一行摘要。空 reasoning 不可展开；有公开摘要、搜索详情或命令输出时才展开。状态文字、颜色、图标及运行耗时区分等待与结果，不读取或承诺提供隐藏推理。
- 中文强调使用 CJK 友好的 Markdown 解析，修复 `**句号在内。**后面紧接中文` 的加粗；原始 Markdown 与源码复制保持不变。
- 本地文件引用展示文件名和行号。悬停、聚焦或点击显示完整路径及前后各五行；Ctrl+点击或预览卡按钮调用 WSL 的 `code --reuse-window --goto`。需要安装 VS Code 与 Remote WSL 扩展。程序只在用户明确点击后启动，失败会显示错误。
- 文件引用支持绝对路径、相对 cwd 的路径、`:行号[:列号]` 和 `#L行号`。预览只允许授权目录内、非隐藏的 UTF-8 普通文件，最大 256 KiB；越界、隐藏配置、二进制、失效行号均明确报错。文件引用装饰与预览不会进入源码复制。
- 回复中的本地 Markdown 图片可直接显示，支持授权目录内、非隐藏的 PNG/JPEG/WebP，最大 25 MiB；按实际文件内容识别格式，自动适应阅读区宽度。复制仍保留原始 Markdown 图片路径，远程图片不自动加载。
- `mermaid` 代码块默认显示浅色图表，可切换／复制源码、放大拖动和下载 SVG。放大窗口支持适应窗口、原始大小、最高 400% 缩放及 Esc 返回；超大图可缩小至适应窗口。页面与下载使用同一份图表。图表接近视口时才加载与排版；流式围栏闭合后渲染，后续正文追加保留图表状态，完成消息中的未闭合围栏也会尝试渲染。源码超过 32,000 字符、超过 Mermaid 的 500 条边限制或解析失败时保留源码并显示原因。图内配置固定，不加载图片、外部资源或执行点击动作；不支持需要 HTML 标签的图表内容。完整 Markdown 与选区复制仍保留原始围栏。
- 外部网页链接显示域名，悬停／聚焦显示完整 URL 并可复制；不自动访问网页获取摘要。系统通知只有用户主动授权且页面隐藏时才发送，刷新不重复提醒。

历史仍由 Codex 管理。上传副本保存到 `~/.local/share/codex-viewer/attachments`（尊重 `XDG_DATA_HOME`，也可指定 `--data-dir`），30 天后自动删除，仅删除本应用命名的上传副本；原文件不受影响，旧任务附件届时可能无法再次读取。文本草稿保存在此浏览器 localStorage，附件草稿仅保存在当前页面内存；刷新前请先发送附件。

## 验证

每个独立检出都需要安装依赖，不共享其他构建或检查目录的 `node_modules`。

```sh
npm ci
npm test
```

Linux Chromium 浏览器流程（中文像素回归需要本机 `AR PL KaitiM GB` 常规字体，Debian/Ubuntu 包名为 `fonts-arphic-gkai00mp`）：

```sh
npm ci
npx playwright install chromium --no-shell
npm run test:browser
```

`test:browser` 的前置脚本会自行构建前端。上述 Node 与浏览器流程使用受控模拟 App Server，不调用模型；Skill 全局开关写入模拟服务内存，VS Code 打开由测试替身记录，不修改真实全局 Skills 或启动编辑器。截图位于 `test-results/viewer*.png`，包括首页、键盘焦点、阅读区、输入配置、Skills、审批、文件预览及桌面宽屏布局。

可单独运行 `npm run test:live`：它使用实际 CLI 登录，查询模型／模式／Skill 列表并发起一个短小只读临时任务，会产生模型用量；拒绝所有工具请求，不让模型读取用户文件。该流程中的 Skill 配置写入在临时 `CODEX_HOME` 中测试。前端候选测试不运行这个命令。

`node scripts/check-context.ts` 使用隔离的临时 `CODEX_HOME` 和现有登录验证上下文管理，会产生三个短响应：普通会话、一次真正的上下文切换与笔记恢复、服务重启后的实验会话恢复。原始记录须包含一次 `new_context` 调用与新的上下文窗口。临时凭据副本和测试记录在结束时删除，不修改用户配置。

`node scripts/check-steer.ts` 在隔离临时会话中实测工具执行期间排队追加，以及空输入框下打断并发送三条队列消息；会产生模型用量，只要求模型运行两次短暂的 `sleep`，不读取用户文件。队列保存在当前浏览器，Codex 返回原消息或转交批次的消息 ID 后移除；接收未确认的内容保留供核对，不自动重发。

Linux Chromium 的截图与视口模拟不能证明真实 Windows 字体、Windows Edge、WSL 浏览器连接或系统缩放效果；这些平台差异尚需在目标设备验收。

## 双击启动与 WSL 自启

WSL 已启用 systemd 时：

```sh
npm run service:install -- /home/andantex/projects
systemctl --user enable --now codex-viewer
loginctl enable-linger "$USER"
npm run shortcut:install
```

桌面和 Windows 开始菜单会出现 **Codex Viewer**。双击会启动对应 WSL 发行版和服务，等待就绪，读取最新登录链接并打开默认浏览器；无需复制链接。重复打开不会重启正在运行的任务，也不会重复创建后台驻留进程。WSL 中也可以运行 `npm run open`；`node scripts/open.ts --check` 仅检查服务就绪，不打开浏览器。

浏览器标签、收藏夹、侧栏、通知和 Windows 快捷方式共用 `c/` 标志。原图保存在 `web/assets/logo-source.png`；`node scripts/icons.mjs` 用已有 Chromium 生成 PNG 和包含 16–256 px 的 ICO，`npm run shortcut:install -- --icon-only` 只更新现有 Viewer 快捷方式的图标。Windows 图标副本保存在本机 `%LOCALAPPDATA%\Codex Viewer\icon.ico`，WSL 未启动时也能显示。

`enable` 与 `enable-linger` 使用户服务随该 WSL 发行版启动；后者允许用户服务在没有交互登录时运行。这不等于 Windows 登录时自动启动 WSL。WSL 的 systemd 服务本身不会阻止发行版空闲退出，因此双击入口在后台保留一个等待进程，直到服务停止或 WSL 关闭。关闭浏览器后任务和 Watchdog 可以继续；电脑仍需保持开机、唤醒。停止服务可用 `systemctl --user stop codex-viewer`，取消服务自启可用 `systemctl --user disable codex-viewer`。

安装命令只创建新文件，不覆盖已有 unit 或快捷方式；`service:install` 本身不启用或启动服务。unit 保存安装时的 Node 路径、PATH、已设置的代理变量及 `CODEX_HOME` / `XDG_DATA_HOME`；迁移项目或 Node、改变代理后需更新 unit，迁移项目或 Node 后也需重建快捷方式。服务启动链接位于 `$XDG_RUNTIME_DIR/codex-viewer-<uid>/url`，未设置该变量时位于 `/tmp/codex-viewer-<uid>/url`；也可用 `--runtime-dir` 指定。快捷方式使用标准用户 runtime 目录，适配上面的默认 unit。不修改 Codex 全局配置、不安装 Windows 服务。

## 实现与参考

Vue 3 + TypeScript + Vite，后端沿用 Node HTTP/SSE；unified/remark 解析、rehype-sanitize 清洗、KaTeX 排版。原始 Markdown 与展示分离，AST 源码位置用于复制，服务端有序事件与快照用于重连。

组件通过具名操作访问统一会话状态，HTTP/SSE 连接由应用生命周期管理；前后端复用 `shared/protocol.ts` 的事件合并规则。会话读取按请求代次处理，快照与实时事件按会话合并，选区存在时只暂停对话显示更新。模块职责、资源释放和后续扩展方式见 [ARCHITECTURE.md](ARCHITECTURE.md)。本轮建立扩展边界，运行时插件热插拔留待具体扩展需求实现。

代码块与命令共用 `web/highlight.ts` 的 lowlight 高亮，命令输出通过同一模块安全呈现 ANSI 颜色。不猜测普通日志的语言；折叠内容按需渲染，缓存有上限，超长文本退回纯文本，复制仍取源码。这里不是完整终端模拟器，不重放光标控制或执行输出中的链接。

Mermaid 12 按需加载，SVG 缓存最多 32 项、总计 4 MiB；图表布局串行执行，进行中的布局无法强制中止，过期结果不会重新插入页面。`lodash-es` 覆盖到 4.18.1，修复 Mermaid 的 Chevrotain 间接锁定旧版本带来的依赖漏洞。

协议以已安装 CLI 生成的 schema 为准；官方文档：[Codex App Server](https://developers.openai.com/codex/app-server/)。先保持这一条运行链路；只有需要原生窗口、系统托盘或独立打包时才考虑 Rust/Tauri。
