# 接手与子智能体

> 历史记录：2026-10-18 已移除 Viewer 的 Google/Antigravity 接入及跨运行时切换。本文记录此前实现与验收，不代表当前支持范围。Codex 子任务委派继续保留。

2026-10-17。混合执行只保留这两种方式。

## 接手

在会话顶栏点击“接手”，直接切换到另一后端。Viewer 先停止原执行并等待原生确认，再创建或恢复接手者的原生会话；切换本身不发送提示词、不启动模型轮次。历史上下文暂存，随下一条实际消息提交。会话 URL、既有消息 ID、引用锚点和草稿保留；消息标明来源，交接处显示接手记录。再次切回时复用已有原生会话。

交接包括 Viewer 已保存的公开消息、工具结果、当前目标和引用信息。已有工作文件仍在原目录；接手者须读取项目规则。首次传递历史，后续补充此前未传递的记录。直接注入的上下文有大小限制，包内明确标出完整记录数量、已加载数量和索引偏移；`viewer_agents.read_context` 能逐条、分段读取剩余记录。长记录不会被静默截断。历史中的附件路径保留，参与交接的现存上传附件不再按 30 天策略清理。

原生运行时的隐藏推理、认证凭据和未向 Viewer 提供的数据不属于可移交历史。早期记录若只有图片占位符，无法据此还原原图。接手不会复制模型账户或权限：Google 使用自身权限，Codex 使用自身沙箱配置。原执行者的 Goal 会暂停，旧后端 Watchdog 在交出主任务后不会启动；切回后原有监控可再次运行。

## 子智能体

主智能体可调用 `viewer_agents.spawn_agent`，选择 Codex 或 Antigravity、具体任务以及不继承、选定记录或完整历史。Viewer 为子任务复制当前工作目录所属项目的普通文件，包含未提交和未跟踪修改。Git 与非 Git 项目均支持，副本拥有独立 Git 基线，不共享源仓库索引、引用或钩子。

`.git`、依赖和构建目录、运行数据、符号链接及特殊文件不会复制，遗漏清单交给子任务。上限为 50,000 个文件或 2 GiB；超限或复制期间源文件变化会失败。副本不是 OS 安全沙箱；特别是 Google 的文件访问能力仍由其原生执行环境决定。

原生 Codex 子代理工具保持原样，原生子代理和 Viewer 派发的子任务共用现有层级面板。Viewer 工具使用 MCP 命名空间，ID 不能交叉传给原生工具。可列出、等待、追加任务、中断、关闭和恢复；运行中的子任务须先等待或中断，再追加指令。Viewer 子任务详情支持追加任务、停止和原生审批，原生子代理保持只读。

子任务结束后，结果和文件变更信息会在主任务空闲且没有待处理审批时自动回传到当前接手者，由主智能体决定继续派发或采用修改。采用时先读取 `agent_changes`，再用该 revision 调用 `apply_agent`。三方合并保留主目录的独立修改；冲突预检不会写回其他文件。写回中发生新的源修改时，返回可能已部分应用的明确错误，日志保留已写回状态，禁止覆盖后续人工修改。合并沿用现有用户授权，没有额外审阅模式。

## 持久化与恢复

逻辑会话、运行时绑定和操作回执保存在 `hybrid.sqlite`；工作副本、基线、清单和合并日志保存在 `agent-workspaces/`。每个变更请求需要稳定 `operationId`。重复的相同请求返回原回执，改变参数复用 ID 会冲突。HTTP 接受不等于执行成功。

进程丢失或重启后，未确认执行标为 unknown，不自动重放。用户可核对记录后恢复会话；旧回执仍保持 unknown。结果回传本身若未确认，也不会自动重发，可让主智能体读取子任务记录。工作副本和保留附件不自动删除。

主要接口为 `POST /api/threads/:id/handoff`、`POST /api/threads/:id/agents`、`POST /api/threads/:id/agents/:agentId/:tool`。协作回执可从 `GET /api/threads/:id/operations` 读取。MCP 身份来自原生调用元数据；模型不能自行填写调用者身份。只有直接父会话能控制和合并子任务。

## 验证

- 服务测试覆盖双向接手、稳定 ID 与引用、重启恢复、停止正在执行的任务、长历史分段读取、原生子代理共存、独立副本、结果仅回传一次、权限范围、版本变化与三方合并冲突、崩溃后不重放。
- 桌面浏览器验证同 URL 双向接手、草稿与作者保留、现有子代理面板以及子任务审批。
- 真实 Antigravity 接收测试历史并正确回忆标记，通过真实 MCP 派发模拟 Codex 子任务，自动回传后继续回复。
- 真实 Codex 从模拟 Antigravity 会话接手，通过真实 `viewer_agents.read_context` 读取历史并正确回复标记。此测试发现并修复新建空 Codex 会话不支持读取轮次的问题。

真实测试均为有界、无文件修改任务；不将它们表述为两个真实模型共同完成复杂开发任务的证明。Web 与 Obsidian 构建、浏览器运行及常用服务是否已更新分别报告。
